## The Big Idea

Until now every line of your program ran, top to bottom, every time. **Conditionals** (a.k.a. selection statements) let you choose which parts of your program run based on conditions that aren't known until the program is actually running.

These concepts exist in *every* programming language — Python just happens to be how we're practicing them this semester.

## Operators Quick Reference

### Relational operators
Compare two values and produce `True` or `False`.

| Math symbol | Python | Meaning |
|---|---|---|
| > | `>` | greater than |
| < | `<` | less than |
| ≥ | `>=` | greater than or equal to |
| ≤ | `<=` | less than or equal to |
| = | `==` | equal to (a question, not assignment) |
| ≠ | `!=` | not equal to |

> **Common mistake:** `=` assigns a value to a variable. `==` asks "are these equal?" Using one when you mean the other is one of the most common bugs in introductory programming.

### Logical operators
Combine Boolean expressions. Python lets you write these as plain English words.

**`or`** — True if *at least one* operand is true.

| A | B | A or B |
|---|---|---|
| T | T | T |
| T | F | T |
| F | T | T |
| F | F | F |

**`and`** — True only if *both* operands are true.

| A | B | A and B |
|---|---|---|
| T | T | T |
| T | F | F |
| F | T | F |
| F | F | F |

`not` inverts a Boolean: `not True` → `False`.

## if / elif / else

### Basic if
```python
x = int(input("x: "))
y = int(input("y: "))

if x < y:
    print("x is less than y")
```
If the condition is `False`, the indented block is skipped silently — no error, just nothing printed.

### Three separate ifs (avoid this)
```python
if x < y:
    print("x is less than y")
if x > y:
    print("x is greater than y")
if x == y:
    print("x equals y")
```
This works, but Python evaluates all three questions every time, even though at most one can be true. It's also harder to read and debug.

### if / elif / else (preferred)
```python
if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
else:
    print("x equals y")
```
`elif` is short for "else if" — it only runs if the previous condition was `False`. `else` is the catch-all that runs if nothing above was true. This structure is cleaner and more logically accurate when conditions are **mutually exclusive**.

> **Rule of thumb:** When you know only one branch can ever be true, use `elif` and `else` instead of separate `if` statements. It's faster to read, easier to debug, and correctly expresses your intent.

## Worked Example: Letter Grade

### Version 1 — with and + explicit upper bound
```python
score = int(input("Score: "))

if score >= 90 and score <= 100:
    print("A")
elif score >= 80 and score <= 89:
    print("B")
elif score >= 70 and score <= 79:
    print("C")
elif score >= 60 and score <= 69:
    print("D")
else:
    print("F")
```

### Version 2 — Python chained comparison (syntactic sugar)
```python
if 90 <= score <= 100:
    print("A")
elif 80 <= score <= 89:
    print("B")
# ...
```
Python lets you write `90 <= score <= 100` just like you would in math class. Most other languages don't allow this.

### Version 3 — drop the redundant upper bound (cleanest)
```python
score = int(input("Score: "))

if score >= 90:
    print("A")
elif score >= 80:
    print("B")
elif score >= 70:
    print("C")
elif score >= 60:
    print("D")
else:
    print("F")
```
Because each question is only asked when all previous ones were `False`, we already know the score is below 90 when we reach the second branch. Checking `<= 89` again is redundant. This is the cleanest version.

> **DRY principle:** "Don't Repeat Yourself." If the structure of the code already tells you something, don't write it again explicitly.

> **Classic typo to avoid:** Writing `score >= 90 and <= 100` is a syntax error. Python doesn't assume "score" on the right side. Every relational operator needs a complete value on both sides: `score >= 90 and score <= 100`.

## Key Vocabulary

| Term | Meaning |
|---|---|
| **Boolean expression** | Any expression that evaluates to `True` or `False`. Named after George Boole. Pronounced "BOO-lee-un." |
| **Conditional / selection statement** | A structure (`if`, `elif`, `else`) that decides which block of code runs. |
| **Relational operator** | Compares two values: `>`, `<`, `>=`, `<=`, `==`, `!=`. |
| **Logical / Boolean operator** | Combines Boolean expressions: `and`, `or`, `not`. |
| **Mutually exclusive** | Conditions where only one can be true at a time (like less than, greater than, equal to). |
| **Syntactic sugar** | A convenient shorthand the language allows, like Python's chained comparisons `80 <= x <= 90`. |
| **Code trace / flow chart** | Walking through code step by step, tracking what runs and what doesn't. Rectangles = statements; Diamonds = decisions. |
| **DRY** | "Don't Repeat Yourself" — avoid writing redundant code. |
