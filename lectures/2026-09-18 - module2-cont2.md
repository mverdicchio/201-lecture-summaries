## Tuples

A **tuple** is an ordered, indexed sequence — like a list — but **immutable**: once created, it cannot be changed.

```python
point = (3, 7)          # a 2D coordinate
color = (255, 128, 0)   # an RGB value
empty = ()              # empty tuple
single = (42,)          # singleton — trailing comma required
```

The trailing comma on a singleton is mandatory. Without it, `(42)` is just an integer in parentheses, not a tuple.

### Indexing (same as lists)

```python
point[0]    # 3
point[-1]   # 7
```

### Immutability

```python
color[1] = 255   # TypeError: 'tuple' object does not support item assignment
```

Tuples are immutable on purpose. Use a tuple when you want to guarantee a structure won't be modified — for example, as dictionary keys, or to protect data you're passing around.

**List vs. Tuple:** if a list is a whiteboard (editable), a tuple is a photo of that whiteboard (fixed).

| | List | Tuple |
|---|---|---|
| Syntax | `[1, 2, 3]` | `(1, 2, 3)` |
| Mutable | Yes | No |
| Indexing | Yes | Yes |
| Use when | You need to add/remove/change items | Structure is fixed |

## Tuple Unpacking (Multiple Assignment)

You can assign multiple variables at once from a tuple:

```python
point = (3, 7)
x, y = point      # x = 3, y = 7
```

The number of variables on the left must match the number of items in the tuple exactly, or you get a `ValueError`.

### Practical use: `str.split()`

`split(delimiter)` breaks a string at every occurrence of the delimiter and returns the pieces as a list (or tuple). Combined with unpacking:

```python
fraction = "33/44"
numerator, denominator = fraction.split("/")
```

This is more readable than indexing into the result manually.

## String Slicing

Strings are indexed sequences of characters — you can slice them just like lists.

```python
name = "Citadel"
#       0123456
```

### Basic slice syntax

```python
name[0:3]    # "Cit"  (characters at index 0, 1, 2 — stop is exclusive)
name[2:5]    # "tad"
name[3:7]    # "adel"
```

### Omitting start or stop

```python
name[:3]     # "Cit"  (start defaults to 0)
name[3:]     # "adel" (stop defaults to end)
name[:]      # "Citadel" (whole string)
```

### Negative indexing in slices

```python
word = "python"
word[-3:]    # "hon" (last 3 characters)
word[:-2]    # "pyth" (everything except last 2)
```

### Step value

```python
s = "abcdefg"
s[::2]       # "aceg" (every other character)
s[::-1]      # "gfedcba" (reverse the string)
```

`s[::-1]` is the standard Python idiom for reversing a string.

### Practical example: parsing a filename

```python
filename = "report.pdf"
extension = filename[-3:]    # "pdf"
base = filename[:-4]         # "report"
```

### Slicing is forgiving

Unlike direct indexing, slices don't raise errors on out-of-bounds values — they just clamp to the string's actual bounds:

```python
s = "hello"
s[1:10]    # "ello" (no IndexError — stops at end)
s[3:1]     # "" (reversed range returns empty string, no error)
```

## Code Tracing

A key exam skill: trace through a loop by hand, tracking each variable's value at each step.

**Example:**
```python
i = 1
total = 0
while i < 5:
    total += i
    i += 1
print(total)
```

| i | total | i < 5? |
|---|---|---|
| 1 | 0 → 1 | True |
| 2 | 1 → 3 | True |
| 3 | 3 → 6 | True |
| 4 | 6 → 10 | True |
| 5 | (exit) | False |

Output: `10`

Practice tip: for any tracing problem, list your variables, write their starting values, then step through the loop one iteration at a time.

## Averaging a List (two idioms)

```python
scores = [88, 77, 99, 65, 100]

# Idiom 1 — index-based for loop
total = 0
for i in range(len(scores)):
    total += scores[i]
print(total / len(scores))

# Idiom 2 — value-based for loop (more Pythonic)
total = 0
for score in scores:
    total += score
print(total / len(scores))

# Shortcut (when a loop isn't required)
print(sum(scores) / len(scores))
```

If a test says "use a for loop," use idiom 1 or 2 — not the `sum()` shortcut.
